# 《今天也在養小孩》MVP UI/UX 設計規格

## 1. 設計目標

MVP 的介面方向是「溫暖的家庭生活手帳 × 資訊豐富的模擬遊戲 Dashboard」。玩家應能持續掌握家庭成員、生活資源、故事進度與過往選擇，同時將注意力留在當下正在發生的家庭故事。

可以參考《80億分之1》讓玩家隨時掌握角色資訊、生活狀態與事件紀錄的資訊架構，但不得複製其視覺風格、版面、身份檔案形式、人生紀錄形式或素材。遊戲使用自有的家庭角色、生活場景與插畫語言。

### 設計原則

1. **故事優先，資訊常駐**：目前事件永遠是最主要的互動焦點；家庭背景、資源與歷史在需要時能立刻取得。
2. **呈現因果，不評分父母**：介面說明選擇、人物反應與後續影響，不使用「好／壞父母」排名、羞辱動畫或道德化紅綠燈。
3. **把隱形負擔寫進故事**：`planningLoad` 等狀態由引擎轉成父母心事、互動與後續事件；UI 不把它簡化成另一條懲罰量表。
4. **階段不等於回合**：介面分開呈現 `AgeStage` 與 `Turn`，不暗示 12 個成長階段只有 12 個事件或 12 個 Turn。
5. **手機是完整體驗**：手機版不是縮小三欄，而是以單欄故事和底部分頁重新安排資訊。
6. **呈現層不擁有規則**：React UI 只呈現引擎提供的狀態與結果，並提交玩家行動；不得自行抽事件、計算反應、改變資源、推進 PRNG 或判定 Turn 結束。

## 2. 視覺語言

### 2.1 氛圍與素材

- 氛圍：溫暖、有人生活過的家庭手帳，保留忙亂、疲累與修復，不做過度夢幻化的「完美家庭」。
- 場景：餐桌、玄關、客廳、廚房、幼兒園門口、公園、通勤與照顧交接等日常空間。
- 素材：原創家庭角色、生活插畫、便條、行事曆、紙張分隔、鉛筆或蠟筆式小圖示。
- 質感：低對比紙張紋理只能作為裝飾背景，不得降低文字可讀性或干擾焦點狀態。
- 禁止：模仿《80億分之1》的身份證件、死亡紀錄、人生履歷版面、像素素材或其品牌辨識。

### 2.2 色彩與字體

初始色彩方向如下；實作時以語意 token 管理，並以實際前景／背景組合驗證 WCAG 2.2 AA 對比：

| Token | 建議色 | 用途 |
| --- | --- | --- |
| `paper` | 奶油白 `#F7F1E5` | 頁面背景 |
| `surface` | 暖白 `#FFFDF8` | 卡片與主要閱讀區 |
| `sage` | 鼠尾草綠 `#8FA38C` | 支持、家庭資訊、次要強調 |
| `sage-strong` | 深綠 `#40594A` | 可讀文字與主要狀態 |
| `terracotta` | 陶土橘 `#C87552` | 當前事件、行動與溫暖強調 |
| `ink` | 墨灰 `#2F302D` | 主要文字 |
| `muted` | 暖灰 `#6D6962` | 次要文字 |
| `line` | 紙邊灰 `#DCD4C7` | 邊界與分隔 |

- 繁體中文介面優先使用清晰的黑體字族，例如 `Noto Sans TC`、`PingFang TC`、`Microsoft JhengHei` 與系統後備字型。
- 正文基準至少 16px、行高至少 1.55；長文不使用左右齊行。
- 手帳字或手寫字只可用於短標籤與裝飾，不得承載事件正文、選項、錯誤或重要狀態。
- 顏色不能是唯一的狀態提示；資源、錯誤、選取與進度都需同時有文字、圖示或形狀差異。

## 3. 資訊架構

遊玩主畫面固定提供六類資訊，桌面可同時看見，手機則透過主要故事畫面與底部分頁分層取得：

| 區域 | 內容 | 目的 |
| --- | --- | --- |
| 家庭檔案 | 家庭組成、孩子年齡、家庭背景與照顧安排 | 建立角色代入感 |
| 家庭資源 | 經濟餘裕、精力、支持、時間彈性、親子連結 | 提供決策脈絡 |
| 主要生活場景 | 地點、時間、原創插畫與環境描述 | 建立故事氛圍 |
| 目前事件 | 情境、對話、人物反應、後續故事與玩家選擇 | 承載核心互動 |
| 家庭生活紀錄 | 已完成事件、重要選擇、支持與修復時刻 | 呈現時間與因果 |
| 父母心事 | 心理負擔、反思、被支持或修復後的變化 | 敘事化呈現隱形負擔 |

`家庭成員`與`成長足跡`是常駐的輔助資訊：前者顯示當下角色狀態與關係語境，後者顯示 12 個 `AgeStage` 的成長進程和已完成的重要里程碑。

## 4. Wireframe

### 4.1 桌面版：三欄 Dashboard

適用於寬度 1024px 以上。中欄是主要故事與唯一主要互動區，建議比例約為 24%／52%／24%；左右欄可在不遮擋內容的情況下維持於視窗內。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 今天也在養小孩    AgeStage 7 / 12 · 3 歲 2 個月    Turn 2    已儲存  選單 │
├──────────────────┬──────────────────────────────────┬──────────────────────┤
│ 家庭檔案         │ 生活場景                         │ 家庭成員             │
│ 成員／家庭背景   │ 原創場景圖、地點、時間           │ 當下狀態／近期行動   │
│ 照顧與工作安排   ├──────────────────────────────────┼──────────────────────┤
├──────────────────┤ 目前事件                         │ 父母心事             │
│ 家庭資源         │ 敘事／對話                       │ 負擔、反思、支持、   │
│ 經濟餘裕         │ 人物反應 → 後續影響              │ 修復的敘事文字       │
│ 精力             │ [玩家選項] 或 [繼續故事]         ├──────────────────────┤
│ 支持             ├──────────────────────────────────┤ 成長足跡             │
│ 時間彈性         │ 家庭生活紀錄                     │ 12 階段與重要里程碑  │
│ 親子連結         │ 最近事件與前次決策               │                      │
└──────────────────┴──────────────────────────────────┴──────────────────────┘
```

桌面行為：

- 頁首同時顯示 `AgeStage x / 12`、該階段的年齡描述與目前 `Turn`，兩者不得合併成單一「第 x 回合」。
- 中欄依故事順序加入 EventNode、人物反應與後續敘事；已提交的內容保留在目前 Turn 的可回看串流中。
- 決策區固定跟隨目前事件，不讓玩家誤把先前事件的按鈕當成當前選項。
- 左右欄資訊可收合，但首次桌面體驗預設展開；收合不改變遊戲狀態。
- 家庭生活紀錄顯示已承諾的結果，不預告尚未觸發的排程事件。

### 4.2 手機版：單欄故事與底部分頁

適用於寬度 767px 以下。主要畫面預設為「生活」，底部分頁固定提供「生活、家庭、紀錄、心事」。`成長足跡`置於「紀錄」，家庭成員與完整資源置於「家庭」。

```text
┌────────────────────────────┐
│ 今天也在養小孩      已儲存 │
│ 3 歲 2 個月 · 階段 7/12    │
│ Turn 2                     │
├────────────────────────────┤
│ [生活場景插畫]             │
│ 地點／時間                 │
├────────────────────────────┤
│ 今天的故事                 │
│ 事件、對話                 │
│ 人物反應                   │
│ 後續故事                   │
│ [選項 A] [選項 B]          │
│ 或 [繼續故事]              │
├────────────────────────────┤
│ 精力 45  支持 68  餘裕 52 │
├────────────────────────────┤
│  生活    家庭    紀錄  心事│
└────────────────────────────┘
```

手機行為：

- 「生活」是啟動遊戲與每次回到遊戲時的預設分頁；只有此分頁呈現當前決策控制項。
- 頁首保留簡短的階段、年齡、Turn 與存檔狀態，不把所有 Dashboard 卡片塞入故事流。
- 故事頁可顯示最多三個最需要決策參考的資源摘要；完整五項資源與說明放在「家庭」。摘要選擇由固定展示規則或引擎提供的展示資料決定，不由 UI 推論事件風險。
- 切換底部分頁不提交選擇、不推進事件，也不重置目前閱讀位置；返回「生活」時保留尚未提交的瀏覽狀態。
- 底部分頁需考慮裝置安全區，觸控目標至少 44×44 CSS px，鍵盤焦點可見。

### 4.3 中間尺寸

768–1023px 採單一主要故事欄加可開啟的資訊抽屜。不得硬塞三個狹窄欄位；抽屜內容沿用相同元件與資訊優先順序。

## 5. 事件呈現與互動狀態

### 5.1 `PLAYER_INPUT_REQUIRED`

- 顯示事件標題、情境、必要對話與 2–4 個引擎提供的可用選項。
- 不可用選項只有在引擎明確回傳原因時才顯示，並以文字說明；UI 不自行判斷資格。
- 每個選項使用完整動作描述，不以 A／B／C 或顏色暗示標準答案。
- 提交時鎖定重複操作並顯示處理狀態；引擎確認後才將選擇寫入生活紀錄。
- 新事件出現後，將可讀焦點移至事件標題；不應讓鍵盤焦點落在已失效的舊選項。

### 5.2 `AUTO_ADVANCE`

- 不顯示偽裝成選擇的按鈕；以「故事正在發展」或相等的中性標籤區分自動節點。
- 引擎仍負責自動推進、節點上限與循環保護。UI 只依序呈現引擎回傳的 EventNode。
- UI 可以做短暫分段揭示，但不可用計時器改變結果。使用者啟用減少動態效果時，立即顯示完整內容。
- 為避免閱讀內容被跳過，每一組自動節點完成呈現後提供「繼續故事」控制；這是閱讀節奏控制，不是遊戲決策，也不改變 PRNG 或狀態結果。
- 自動節點到達 `PLAYER_INPUT_REQUIRED`、Turn 結束、節點上限或安全 fallback 時，畫面必須清楚切換至對應狀態。

### 5.3 人物反應與後續故事

- 人物反應以角色名稱／關係、話語或動作、反應類型的無評價文字呈現。
- `support`、`neutral`、`criticism` 與 `none` 不只靠顏色區分；`none` 可以用「沒有人特別回應」等自然敘事呈現。
- `anticipatedJudgment` 與 `observedReaction` 必須使用不同標籤，避免把父母的擔心誤寫成實際批評。
- 後續故事應接在造成它的事件之後，並在生活紀錄留下可追溯的前因；跨 Turn 或跨 AgeStage 觸發時，顯示「先前發生的事」摘要，但不暴露排程規則。

### 5.4 隱形負擔、支持與修復

- `父母心事`由引擎或內容層提供的敘事片段組成，例如「明明大家都有幫忙，為什麼所有事情還是需要我提醒？」。
- 不直接顯示 `planningLoad +5`、診斷標籤或不可逆的危險刻度。
- 當支持、休息、主動分工或關係修復發生時，父母心事與後續敘事也必須能更新，讓玩家看見負擔被分擔或重新理解。
- 資源變化與敘事變化可以並存，但 UI 不自行將數值翻譯成心理結論。

### 5.5 進度、紀錄與存檔

- 成長進度顯示 12 個 `AgeStage`，每階段可包含多個 Turn；目前 Turn 使用獨立文字顯示。
- 家庭生活紀錄按實際故事順序累積事件、選擇、人物反應、支持、修復與重要里程碑，並能依 AgeStage 分組。
- 存檔狀態至少有「儲存中、已儲存、儲存失敗」三種可讀文字，不能只靠圖示。
- 還原成功後回到確切的 EventNode／Turn 閱讀狀態。損壞或不相容存檔顯示原因、保留資料說明，以及重試、匯出／保留或明確重新開始等安全選項。
- 不得在錯誤後自動清除存檔或未經確認開始新遊戲。

## 6. Component Design

元件名稱描述責任，不限制實作檔名或 CSS 技術。

| 元件 | 責任 | 明確不負責 |
| --- | --- | --- |
| `GameShell` | 組合響應式版面、導覽與全域狀態提示 | 事件選取、規則判定 |
| `GameHeader` | 顯示遊戲名、AgeStage、年齡、Turn 與存檔狀態 | 推進 AgeStage 或 Turn |
| `DesktopDashboard` | 在桌面安排左／中／右三欄 | 改寫各區資料 |
| `MobileStoryShell` | 安排手機單欄故事與底部分頁 | 建立另一套遊戲狀態 |
| `FamilyProfilePanel` | 顯示家庭組成、背景、照顧與工作安排 | 生成或重新解讀家庭 |
| `ResourcePanel` | 顯示五項可見資源、標籤與數值／區間 | 計算增減或失敗條件 |
| `ScenePanel` | 顯示原創場景、地點、時間與替代文字 | 依場景選取事件 |
| `CurrentEventPanel` | 依序呈現目前 EventNode、對話與敘事 | 決定下一個 EventNode |
| `DecisionPanel` | 顯示引擎提供的選項並提交單一玩家行動 | 判斷 eligibility 或套用效果 |
| `AutoAdvancePanel` | 呈現自動節點與閱讀節奏控制 | 執行自動遍歷或循環保護 |
| `ReactionPanel` | 區分預期評價、實際人物反應與無反應 | 抽取 reaction pool |
| `ConsequencePanel` | 顯示即時結果與可理解的後續影響 | 推算尚未觸發的影響 |
| `FamilyLog` | 依 AgeStage／Turn 顯示已確認的生活紀錄 | 顯示未觸發排程事件 |
| `FamilyMembersPanel` | 顯示成員、關係與近期可見狀態 | 推導角色心理或關係分數 |
| `ParentThoughtsPanel` | 呈現隱形負擔、支持與修復的敘事片段 | 自行把數值轉成診斷 |
| `GrowthTimeline` | 顯示 12 個 AgeStage 與重要里程碑 | 假設每階段只有一個 Turn |
| `SaveStatus` | 顯示儲存中、成功與失敗 | 實作序列化或遷移規則 |
| `SaveRecoveryDialog` | 顯示安全復原選項並取得明確確認 | 靜默刪除或覆蓋存檔 |
| `BottomTabNavigation` | 在手機切換生活、家庭、紀錄與心事 | 推進故事或改變 GameState |

### 6.1 UI 與事件引擎邊界

- UI 接收由公開邊界產生、可直接呈現的遊戲快照與事件輸出，並以明確的呈現狀態區分 `PLAYER_INPUT_REQUIRED`、`AUTO_ADVANCE`、Turn 結束、遊戲完成與錯誤。
- UI 只送出玩家選擇、閱讀節奏、存檔、還原、Reroll 與重新開始等命令。只有玩家選擇等引擎定義的行動可改變模擬狀態；分頁、收合、捲動與「繼續故事」屬於本地呈現狀態。
- PRNG state、事件 eligibility、reaction pool、資源更新、排程、Turn 終止與 AgeStage 轉換都由對應的公開領域邊界處理。
- 元件測試使用固定的呈現快照與命令 spy；不得為了測 UI 而複製一套簡化事件規則。

## 7. 響應式與可及性

- 斷點以內容是否可讀為準：桌面三欄（≥1024px）、中間尺寸主欄加抽屜（768–1023px）、手機單欄加底部分頁（≤767px）。
- 所有核心流程可只用鍵盤完成；焦點順序符合視覺與故事順序，焦點外觀清楚。
- 事件更新、人物反應與存檔狀態以適當的 `aria-live` 禮貌播報，不重複朗讀整頁。
- 一般文字與背景至少 4.5:1，大型文字與必要 UI 邊界至少 3:1；實際 token 組合在實作驗收時量測。
- 尊重 `prefers-reduced-motion`；紙張、插畫與進場效果不影響閱讀或操作。
- 插畫提供符合情境的替代文字；純裝飾紙張紋理與圖示不重複朗讀。
- 錯誤訊息指出發生什麼事、資料是否仍保留、玩家可以採取什麼動作。

## 8. UI Acceptance Criteria

### 8.1 版面與資訊架構

- [ ] 1024px 以上的遊玩畫面採三欄 Dashboard：左側家庭檔案／資源、中間生活場景／目前事件／家庭紀錄、右側家庭成員／父母心事／成長足跡。
- [ ] 767px 以下的遊玩畫面採單欄主要故事，底部分頁可查看生活、家庭、紀錄與心事；核心決策不被複製到其他分頁。
- [ ] 768–1023px 不會將桌面三欄壓縮成不可讀窄欄，而以主要故事欄加資訊抽屜呈現。
- [ ] 桌面與手機都持續顯示年齡、`AgeStage x / 12`、目前 Turn 與存檔狀態，且不把 AgeStage 誤稱為 Turn。
- [ ] 版面使用原創家庭生活視覺，不複製《80億分之1》的版面、素材或身份／人生紀錄形式。

### 8.2 事件與故事流程

- [ ] `PLAYER_INPUT_REQUIRED` 只顯示引擎提供的有效決策，提交一次後可防止重複送出，並在新事件出現時正確管理焦點。
- [ ] `AUTO_ADVANCE` 清楚標示為非決策故事節點，UI 不用計時器計算結果，並在自動序列結束後提供閱讀節奏控制。
- [ ] 人物反應、無反應、預期評價與實際觀察有清楚且不只依靠顏色的區別。
- [ ] 同 Turn 的 EventNode 依序保留；跨 Turn／AgeStage 的後續故事顯示可理解的前因摘要。
- [ ] 家庭生活紀錄只加入已確認事件與結果，不洩漏未來排程內容。

### 8.3 狀態、隱形負擔與修復

- [ ] 五項家庭資源可讀、在桌面常駐，並可由手機「家庭」分頁完整查看；任何狀態都不只靠顏色表達。
- [ ] 父母心事以內容層提供的敘事呈現隱形負擔，不顯示 `planningLoad +N`、診斷或好壞父母分數。
- [ ] 當故事發生休息、支持、主動分工或關係修復，父母心事或後續敘事能呈現變化，而非只保留負面累積。
- [ ] UI 不自行從資源或隱性狀態推導心理結論、人物反應、事件資格或未來結果。

### 8.4 存檔、錯誤與可及性

- [ ] 存檔流程有「儲存中、已儲存、儲存失敗」文字狀態；重新載入可回到正確 EventNode 與 Turn。
- [ ] 損壞或不相容存檔顯示資料保留情況與安全復原選項，不靜默刪除或覆蓋玩家資料。
- [ ] 主要流程能以鍵盤完成，焦點可見，事件更新與錯誤可由輔助科技理解。
- [ ] 觸控目標至少 44×44 CSS px，手機底部分頁不被裝置安全區遮擋。
- [ ] 正文使用清晰繁體中文、至少 16px 基準字級，重要內容不使用手寫字體。
- [ ] 減少動態效果模式下可立即閱讀完整自動節點，且不影響遊戲結果。

### 8.5 架構與測試

- [ ] UI 僅透過公開邊界讀取遊戲快照並提交命令；React 元件內沒有 PRNG、事件資格、人物反應、排程、資源轉換或 Turn 終止規則。
- [ ] 元件測試覆蓋五種呈現狀態：玩家輸入、自動推進、人物反應／後續、Turn 結束與可復原錯誤。
- [ ] Playwright 以桌面和手機 viewport 覆蓋一段包含 AUTO_ADVANCE、PLAYER_INPUT_REQUIRED、人物反應、跨節點紀錄與存檔／還原的流程。
- [ ] 自動化可檢查 AgeStage／Turn 標示、底部分頁狀態保持、鍵盤焦點與錯誤復原，不依賴內部 React 實作細節。

## 9. 本階段不包含

- UI 程式碼、最終插畫、動畫成品或完整品牌識別實作。
- 複製參考作品的視覺、版面或素材。
- 將自由探索地圖、即時日程管理、社群帳號或跨裝置同步加入 MVP。
- 由 UI 自行補齊尚未完成的引擎、內容或 persistence 規則。
