第 1–2 節記錄已確認的產品規則；第 3 節依已確認 UI 要求提出呈現方案，具體位置與控制項樣式仍可調整；第 4–7 節的技術方案與驗收案例供審查，尚未實作。
上述為最初設計審查狀態。2026-10-23 使用者已確認首版實作範圍、Ticket 拆分與測試邊界，新增 Spec #28 及 Tickets #29、#30。六項全開、彈性安排預設、1～1.25 倍一般入口權重、外層存檔 v3／內層 v1、不新增解鎖或完整歷程等決議，以 [實作記錄](FAMILY_LIFE_DIRECTION_IMPLEMENTATION.md) 為準；以下待審查標記保留為原始提案脈絡。

## 1. 定義與核心互動

「家庭生活方向」是玩家對中長期家庭生活的策略偏好，常駐於遊玩主畫面。它不是年度目標、AgeStage 任務、家務待辦或能力加點。

- 遊玩中隨時可更換，包含目前事件等待選擇、閱讀已生成故事、Turn／AgeStage 邊界；不要求先完成事件或進入下一階段。
- 同一時間必須且只能有一個有效方向（Single Active Selection）；不能取消成無選取，也不能複選。
- 點擊另一個目前可選方向即更新目前選擇並立即嘗試保存，無確認視窗、資源消耗、冷卻時間、年度或階段次數限制。
- 切換本身不推進故事、時間、AgeStage／Turn、事件節點數或 PRNG，不改寫已發生事件與已確定結果。
- 新方向只適用於之後尚未抽選的事件。已抽中但尚未顯示的事件也已確定；切換不提供重新抽選入口。
- 孩子成長或家庭處境改變可以增加可選方向。既有方向保留，不因跨階段、暫時資源變化或家庭條件改變無故消失，也不自動替玩家換方向。
- 完成遊戲後的家庭紀錄維持唯讀，保留最後方向，不再提供影響模擬的切換操作。

## 2. 候選方向與效果邊界

以下為候選分類，名稱、初始可用集合與後續擴充條件仍可審查調整。

| 候選方向 | 偏好描述 |
| --- | --- |
| 彈性安排 | 隨家庭當下需要保留調整空間 |
| 工作與經濟 | 留意工作安排、收支與生活穩定 |
| 親子陪伴 | 留意共同相處、傾聽與日常互動 |
| 家庭與關係 | 留意家人協調、支持與關係維繫 |
| 照顧者身心 | 留意休息、自我照顧與照顧者需要 |
| 生活探索 | 留意新體驗、興趣與生活環境 |

可以影響後續事件抽選的相對權重、部分敘事或家庭生活摘要。既有遊戲規則支援的資源效果須另行確認，本次不核准直接加減資源、持續加成或新增資源。

所有方向都應保有其他生活面向的事件機會。不得因方向單獨排除其他類別、創造唯一最佳解、預設工作導致親子關係惡化，或保證陪伴讓孩子發展更好。具體事件仍可按當時條件與玩家行動產生資源、支持、衝突或修復效果，不把方向當作道德或能力判定。

### 與「最近的家庭生活」分開

| 功能 | 資料來源 | 互動與語意 |
| --- | --- | --- |
| 家庭生活方向 | 玩家主動選取 | 表達接下來想留意什麼；只有一個有效方向 |
| 最近的家庭生活 | 系統根據實際事件、狀態及人物互動整理 | 描述最近確實發生什麼；不是可選策略 |
| 家庭生活紀錄 | 已確認的事件與玩家選擇 | 可回看歷史；不因目前方向改寫 |

例如選擇「照顧者身心」後，不能立即宣稱家人已經提供休息或支持。摘要可以獨立註明目前偏好，但不能以此替代實際經歷。系統整理出的摘要也不能反過來覆寫玩家方向。

## 3. Gameplay UI

- 桌面三欄的中間主要互動欄，於目前故事區上方設置獨立的「家庭生活方向」手帳區塊；與事件選項及「最近的家庭生活」分開標題。
- 手機「生活」主畫面與中間尺寸的主要故事欄同樣常駐此區塊。所有目前可用方向直接列出並自然換行，不藏進抽屜、下拉選單、輪播、年度目標或階段強制選擇視窗。
- 「常駐」指主畫面的固定資訊區塊，隨事件與階段保留；不要求黏住視窗或遮擋故事。小螢幕可正常捲動看到全部選項。
- 每項顯示名稱與簡短中性描述。選中項使用勾選／「目前方向」文字及邊框共同標示，不只依賴顏色，不放未核准的資源升降箭頭或成效保證。
- 使用有群組標籤的單選控制項，支援鍵盤與輔助科技；焦點保留於操作項，不跳到故事標題。觸控尺寸與色彩沿用既有可及性規格。
- 提示文案：「隨時可更換，影響接下來尚未抽選的故事。」UI 不顯示內部權重、PRNG 或排程細節。
- 採奶油白紙面、鼠尾草綠／陶土橘標記與原創手帳分隔。參考圖僅提供隨時切換的互動語意，不沿用「今年的重心」、膠囊選項排列、配色或附帶功能按鈕。
- 切換後立即反映記憶體中的方向與儲存狀態。失敗時清楚標示「尚未儲存」，提供重試原狀態；不得假稱已保存。短暫處理期間依提交順序串行處理，不以防連點引入遊戲冷卻，也不靜默丟棄有效切換。

## 4. 現況與抽選邊界評估

以下現況來自本次本機程式碼讀取，與未來提案分開。

| 領域 | 現有行為／缺口 | 此功能的影響 |
| --- | --- | --- |
| 事件抽選 | `chooseWeightedEvent` 以穩定事件 ID 排序、正權重與目前 `rngState` 抽一般入口；尚無方向資料 | 在資格過濾後、抽選前加入方向權重；不能用方向取代 eligibility |
| 預先確定事件 | `awaitPlayerInput` 保存待選事件；一次 `ADVANCE` 可處理多個自動節點 | 抽選即確定，不能等畫面出現才套用方向 |
| Session | `execute` 在 `CHOOSE` 後可能立即呼叫一次 `ADVANCE`，閱讀只是呈現狀態 | 該自動序列會使用下一筆切換提交前的方向；不為切換回滾或拆開已完成序列 |
| 排程 | immediate 與 scheduled follow-up 已指定 `eventId`；依優先序與穩定 ID 派送，不抽亂數 | 保留具體事件與既有條件、冷卻、取消、預算及失效規則；方向不重排、不取消、不替換排程 |
| 人物反應 | 節點解決時以 post-choice 狀態抽反應池 | 本次提案只調整一般入口權重；不讓方向改變當前事件的反應、選項或資源結果 |
| AgeStage | 12 個成長里程碑，各可含多個 Turn；有既有節點預算 | 方向跨階段持續，切換不占節點／Turn，不新增年度時鐘 |
| Persistence | 嚴格驗證；外層存檔版本 2、內層 GameState 版本 1；無方向欄位 | 需要明確版本遷移、方向驗證與切換保存接線，不能直接把新欄位塞入舊格式 |
| Gameplay UI | Session 組合唯讀呈現快照與公開引擎／存檔邊界 | 新增方向群組與明確命令；React 不自行決定資格、權重或保存格式 |

### 建議的生效時點（待審查）

1. 每筆遊戲命令按順序處理。方向切換是一筆獨立狀態命令，先完成更新與保存嘗試，再處理下一筆命令；不能插入正在執行的同步引擎轉換。
2. 每次一般入口抽選，用當時已提交至引擎狀態的方向計算權重。選出並記錄待選事件，或解決自動事件時，該次抽選即確定。
3. 切換 A→B 時，當前待選事件仍以原事件繼續；其選項、人物反應與效果沿用既有規則，不因 B 重算。下一次尚未執行的一般入口抽選才讀 B。
4. 一段自動序列若已在一筆命令內跑完，尚未閱讀的內容也已確定。讀完／揭示不消耗亂數，不觸發重新計算。
5. 排程中的具體 `eventId` 是既定後續，不是待抽候選池。即使尚未到期，切換也不改它；派送時仍可因既有條件不符而失效。派送後若再次需要一般入口抽選，才讀最新方向。
6. 目前沒有尚待抽選的隨機事件預取池。未來若新增，須分清「只快取候選」與「已抽中並提交」：前者抽選時讀最新方向；後者保存事件與抽選快照並固定，不因切換失效重抽。未提交的預覽不得消耗正式 PRNG。

例：事件 E 已在 A 方向抽中並等待選擇 → 切 B → 解決 E 及其既有反應 → 派送已指定的 F → 下一次一般入口抽選使用 B。B→A→B 不改 E／F，也不提前抽下一個事件。

## 5. PRNG 與可重現性（技術提案，待審查）

- 新增明確方向命令，例如 `SET_FAMILY_LIFE_DIRECTION(directionId)`，經同一純函式引擎公開邊界處理；不得隱含呼叫 `ADVANCE` 或 Session 的選擇後自動推進。
- 合法切換只改方向相關狀態及命令 trace；`rngState`、目前事件、排程、已選結果、人物狀態與資源保持原值。重複點相同方向為冪等操作；不新增故事節點。無效／尚未解鎖 ID 明確拒絕且不改狀態。
- 建議先限於一般入口事件：有效權重＝原事件權重 × 該事件對目前方向的乘數；未標註乘數為 1。乘數須有限且嚴格大於 0，並設定上下界以防某類事件實質被壓至不可見。確切範圍與內容校準待審查，不在本次指定數值。
- 方向只能修改相對機率；資格、節點預算、冷卻、去重、固定 follow-up 與安全 fallback 都沿用既有規則。方向不能新增 eligibility 排除條件或保證某一事件。
- 保留候選穩定 ID 排序與既有抽選次數：一般入口每次抽選消耗一次 PRNG；切換、唯讀呈現、固定排程派送及 fallback 不新增抽樣。權重運算須避免溢位與非有限值。
- 重播輸入包括全部玩家命令及方向切換在命令序列中的位置，不能只比較最終方向。同 Seed、相同初始設定、相同遊戲操作與切換順序，在相同引擎／內容／權重設定版本下，完整事件結果與 PRNG trace 必須相同。
- 存檔續玩使用目前 `rngState`，不以 Seed 重建亂數進度。若抽選演算法或內容權重改版，需明確處理版本相容；不承諾不同內容版本重播相同故事。
- 引擎 trace 應能辨識方向命令與抽選當時的方向；是否另持久化完整切換歷程屬第 6 節審查項目。現在的事件／選擇歷史不能冒充完整命令紀錄。

## 6. Schema、引擎與存檔影響清單（供審查）

以下欄位名稱是提案，不是已修改的契約。

| 提案 | 影響範圍 | 審查重點 |
| --- | --- | --- |
| 方向定義 catalogue：穩定 ID、名稱、描述、顯示順序 | Domain／ContentPack、內容驗證、呈現快照 | 初期是否六項全開；名稱變動不換 ID；不重用事件分類推斷方向 |
| `GameState.activeFamilyLifeDirectionId` | 家庭建立、引擎、保存／還原、唯讀快照 | 非空且必須指向已知可用方向，維持單一生效；建議新局預設「彈性安排」，避免強制選擇視窗，待確認 |
| 累積已解鎖方向 ID（如 `unlockedFamilyLifeDirectionIds`） | GameState、解鎖規則、AgeStage／家庭狀態更新、Persistence | 若首版全開可先不需此欄位；若動態解鎖，依確定性條件累積，已解鎖保留，不以即時 eligibility 使方向消失；條件與擴充清單待確認 |
| EventNode 的方向權重映射 | Domain、ContentPack 驗證、一般入口抽選、內容編寫 | 穩定方向引用、正乘數上下界、未標註中立；不修改現有 reaction `weightModifiers` 以免擴大效果 |
| 方向狀態命令與結果／trace | EngineInput、EngineTransition、getPlayerView、Session | 在等待輸入與生命週期邊界都可用；保留 pending event 與目前 mode；不得套用只適用故事推進的結束／預算檢查 |
| 切換序列及抽選來源紀錄 | 測試重播、偵錯；若持久化則影響 GameState／Persistence | 最小方案為外部命令 trace 重播＋存檔保存目前方向；若要求單靠存檔還原完整歷史，須另存命令序號、方向、當時 stage／Turn 與抽選快照；同 Turn 可以切換多次，不能只靠 Turn 當順序 |
| 新存檔版本與顯式遷移 | save-format、player-save 相容檢查、local-save-store、Session 恢復 | 建議升外層版本，內層版本是否同步變更須統一決定；沿用原始資料保留、失敗可復原與 expected bytes 衝突檢查 |
| Gameplay 方向群組與保存提示 | getPlayerView／GamePresentation、player-session、GameScreen、響應式樣式 | 命令串行、所有可用方向可見、單選可及性、切換立即存檔、失敗可重試；不走 CHOOSE 自動推進路徑 |

### 遷移與保存建議

舊檔沒有方向時，建議遷移為「彈性安排」並加入初始可用集合，保留目前事件、排程、選擇、資源、家庭與 `rngState` 原值；不補造過去切換、不重抽歷史。這個預設與遷移方案仍待確認。若權重改變，舊檔遷移後的尚未抽選未來可能不同於舊版本；已確定部分仍固定。

已帶方向的新格式若包含未知／損壞 ID，應依現有不相容／損壞存檔流程保留原始資料並回報，不靜默回到預設。移除方向或變更 ID 必須另設明確版本遷移，不藉版本更新無故收回選項。

每次有效切換立即透過 Save / Restore Boundary 保存，沿用原始位元組比對。儲存失敗保留記憶體中更新後的狀態並明示尚未保存，暫停後續模擬命令直至重試成功或重新讀取；重試只保存該狀態，不重送切換／選擇或抽樣。衝突時重新讀取最新存檔，不覆蓋其他分頁。重整只能恢復最後成功保存的狀態，不能把失敗寫入承諾為持久化成功。

「最近的家庭生活」不與方向共用欄位；若未來需要快取摘要，應另行定義來源與失效規則，本次不新增摘要生成器或摘要 Schema。

## 7. 未來實作驗收案例

本節定義測試範圍，這次文件更新不新增或修改測試。優先沿用公開引擎、Persistence 與 Session 整合測試，UI 元件只驗證呈現及命令提交。

| 案例 | 預期可觀察行為 |
| --- | --- |
| 主畫面切 A→B→C、重複點 C | 任何時刻一項有效，逐次立即更新與保存；重複項冪等；資源、PRNG、節點數與時間不變 |
| 待選事件抽中後切換 | 待選 ID、選項與已確定敘事保持；既有反應規則不因方向改變 |
| 自動事件已生成但尚未閱讀 | 切換與揭示都不重跑；下一次未抽選的一般入口才使用新方向 |
| 固定排程與跨階段 follow-up | 切換不替換、取消、重排既定事件；原有條件、冷卻、預算與失效仍有效 |
| 跨 Turn／AgeStage、解鎖新方向 | 現有方向與選取保留；新增方向不強制打斷故事；切換不消耗節點 |
| 相同 Seed 與完整命令序列重播 | 相同版本下事件、反應、資源與 PRNG trace 一致；包含同 Turn 多次切換與等待輸入時切換 |
| 抽選前／後、切換後保存並重整 | 與不中斷執行的對應後綴一致；已抽中事件不因還原重新抽選 |
| 權重及中立內容 | 驗證正權重、穩定排序、未標註為 1；所有原合法類別保持正機率；不以少量隨機樣本宣稱一定公平 |
| 空候選／低資源／反覆切換 | fallback 與終止保護仍工作；不給重抽既定結果的機會，不以方向造成必敗或必勝 |
| 儲存拒絕、額度不足、分頁衝突 | 失敗可見、原檔保留、重試不重抽；衝突不覆蓋；成功後重整恢復最新方向 |
| 舊檔遷移與無效方向 | 已確認的遷移預設不改歷史與 PRNG；未知 ID 不靜默修復；保留原檔 |
| 桌面／手機／鍵盤 | 所有可用方向可見、當前項清楚、單次操作切換，無年度／階段視窗；焦點與保存提示正確 |
| 方向與生活摘要 | 切換不捏造已發生的照顧、支持或親子成果，摘要不覆寫方向 |

審查時需確認：初始／遷移預設、初始可用方向、解鎖條件、權重幅度、是否持久化完整命令歷程、存檔版本策略；資源效果另外立案確認。以上未定項不影響本文件已確認的隨時單選互動與既定事件不重抽原則。
