# 開場與家庭成員工作紀錄

- 先讀 Schema 與條件實作，再區分「家庭有這個人」與「當下人在場」。後續正式情境應先建立出席、物品、備餐事實的來源與生命週期，避免文案先承諾不存在的狀態。
- 此環境的預設 Vite／Vitest 設定打包會嘗試讀取父目錄。使用 npm scripts 搭配 `--configLoader runner` 可在原沙箱權限內完成測試與建置，無需擴大權限。
- 多工負載下，多步驟 UI／三種家庭 Session 案例可能超過預設五秒。測驗元件直接測試呈現與選擇；完整 App 導覽交給 E2E，避免重複掛載不相關首頁。跨情境案例採明確十五秒上限，完整測試限制一個 worker，保留所有行為斷言。
- 參考截圖應在開始時確認是否實際收到；缺少截圖不阻擋文字需求實作，但交付須明確區分本地截圖檢查與參考圖比對。
- 本輪補上 01–04.jpg 後，確認家庭資訊實際位於 01.jpg；04.jpg 是精簡紀錄。依可見內容對應需求，避免僅依先前的圖片編號推定改版範圍。人物近況應沿用原始事件時間，不能用當前年齡標示舊反應。
- 測試沿用公開邊界，桌面與手機共用成員元件；不用額外建立家庭模型或用假資料填補缺欄位。
