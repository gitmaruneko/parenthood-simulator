依據：本次使用者需求、MVP Spec、UI/UX Spec、Family opening、Domain Schema、Event Engine、Player UI，以及相應實作。使用者於續作時補上 01–04.jpg，已完成資訊層次與本機畫面的比對。

## 參考圖比對與續作範圍

- 01.jpg 右上「家人與生活」：借鏡關係、稱呼／年齡、背景摘要的資訊層次。沿用本遊戲紙張、鼠尾草綠與手帳視覺；不複製身份證、像素素材或家庭角色配置。
- 02.jpg「今年的重心」：本遊戲既有家庭生活方向已是可隨時切換的單選，本次維持既有行為。
- 03.jpg 事件彈窗：借鏡具體選項敘事，不擴增重做彈窗，也不改動事件引擎。
- 04.jpg「人生紀錄」：對應本遊戲既有精簡家庭生活紀錄；維持最新在上、年齡／天數、事件與選擇，不複製參考作品的具體人生敘事。

續作將家庭成員身份列排得更精簡，先顯示家庭照顧／工作短摘要；近況標示原始故事時間，展開可讀該角色最近三筆既有關係記憶。稱呼與關係相同時只顯示一次，不用重複文字填充缺少的姓名資料。

## 可直接完成的範圍

- 五題開場測驗仍可跳過，只影響當下敘事傾向，不改變家庭、資源、PRNG、事件資格或結局。前兩題各六種候選行動，預設四項，以「看看其他做法」展開其餘兩項；不強迫單次畫面顯示六項。
- 晚餐候選涵蓋原計畫煮飯、簡單煮、家人備妥飯菜、外食／外帶／外送、請家人幫忙、先休息。餐廳候選涵蓋安靜處、輪流陪伴吃飯、手機／平板、安撫玩具、外帶、座位安撫。家庭尚未生成，題目和有條件的行動均明示假設，沒有預設伴侶或公婆同住。
- 手機與玩具採相同中性的虛構敘事傾向權重，不建立正誤判定，也不承諾安撫一定成功。既有答案 ID 保留。
- 家庭成員沿用家庭生成的 actor displayName，只顯示 childId 與 persistentActorIds 對應角色。顯示孩子當前階段年齡、共同照顧／同住長輩／不同住支援關係、已記錄的最近人物反應。成人卡片可展開家庭照顧與工作安排，明確標示為家庭層級，不能當成個人職業。
- 桌面與手機使用同一成員元件；閱讀、展開及收合不提交引擎命令。近況隨 Session 快照更新，缺少近況不顯示該欄，不捏造人物行動。時間使用該反應的 Turn 標籤，不套用目前階段；個別片段僅取 actorId 相符的記憶，無角色歸屬的家庭記憶不掛到人物身上。

## 既有契約與正式事件限制

`EventChoice.requirements` 已支援 flag、actorAvailable、contextTag、location 及組合條件。引擎過濾不符合的選項，且拒絕選擇不可用的選項。EventNode 仍為 2–4 項；開場測驗獨立於 EventNode，新增候選不修改此上限。

`actorAvailable` 在選項判斷時只確認家庭角色 ID，並不保證人在現場、願意協助或有空。`contextTag` 是作者寫在事件上的標記，不是物品持有或角色出席紀錄。`flag` 能記錄既有事件確立的事實，但目前沒有「飯已煮好」「帶了安撫玩具」「帶了手機」「餐廳同行者」的產生及清除契約。不可僅憑家庭有長輩就敘述飯已煮好，也不可僅憑有另一位照顧者就寫他正在餐廳。

正式內容已有「餐桌前的準備」；沒有餐廳哭鬧 EventNode。本次保留既有正式備餐事件及角色條件，不將開場測驗六項直接搬入正式事件，不重寫 Event Engine 或 Family Generator。

## 待確認的阻塞項目

| 需求 | 缺少的正式資料／語意 | 待確認決策 |
| --- | --- | --- |
| 人物姓名 | actor 現只有角色稱呼 displayName，生成器不產生個人姓名 | 是否新增個人姓名欄位，或擴充 displayName 的生成與保存規則 |
| 成人年齡 | 無年齡、出生時間或時間推進規則 | 出生日期或開場年齡的資料型別、時間推進及舊存檔相容方式 |
| 個人工作／背景 | workArrangement 僅描述家庭，無個人職業／生活背景 | 角色層級職業、生活背景及可變狀態的生成與持久化契約 |
| 孩子特質 | actor 無 temperament／特質資料 | 特質定義、來源及可變規則，不能由測驗答案推定 |
| 餐廳輪流陪伴 | 無實際同行者清單／在場及支援意願 | 使用已建立的事件事實旗標或擴充出席契約；角色存在仍須一併判斷 |
| 玩具、手機／平板 | 無持有、攜帶、當下可使用狀態 | 物品來源、作用範圍、消失／重置方式；不得憑空將旗標設為 true |
| 家人已備好飯 | 無備餐完成、備餐者、當日有效性 | 作者事件如何建立與清除此事實，並確認角色存在及同住關係 |
| 正式事件涵蓋全部候選 | 2–4 項上限不能容納全部，餐廳尚無事件 | 確認情境變體及選項分組，再以既有條件機制撰寫；不先擴大上限 |

角色目前由 seed 經 Family Generator 重建，而非獨立保存人物檔案。新增姓名、年齡或職業若改變抽樣順序，會影響相同 seed 的重建與既有存檔；須另行確認版本與相容策略。

## 驗收切片

1. 開場：六種候選可選、初始四項、展開不答題、下一題收合、仍可跳過；生成與傾向隔離。
2. 成員：三種家庭組成只呈現實際角色，既有條件選項依角色存在顯示；孩子年齡隨階段更新，成人無捏造年齡。
3. 近況：人物反應更新及存檔恢復使用同一資料，桌面／手機共用摘要與詳情，展開不改變遊戲。

本次未發佈 GitHub issue、未改動核心 Schema、未新增正式餐廳事件。
