# 《今天也在養小孩》Game Design Document（GDD）

- **專案代號**：Parenthood Simulator
- **文件版本**：v1.0（開發基準）
- **日期**：2026-10-20
- **類型**：敘事人生模擬 × 家庭資源管理 × 育兒知識
- **目標平台**：手機優先的繁體中文網頁（桌機相容）
- **開發方式**：Codex 協作；React / TypeScript / Vite；靜態部署
- **狀態**：待製作原型及內容審核

> **一句話理念**：養小孩沒有標準答案，但每個選擇背後，都有一個家庭正在努力生活。

## 1. 產品願景與原則

玩家扮演照顧者，陪伴孩子從出生到六歲。遊戲不只呈現孩子的哭鬧、飲食和發展，還要呈現備餐、預約、請假、家務規劃、職涯、伴侶溝通、長輩期待、大眾運輸、社會眼光等「不被看見的照顧工作」。

**設計支柱**：
1. **真實的兩難**：選項代表需求與資源的取捨，不是教養正誤題。
2. **看見隱形負擔**：區分執行工作、記得工作、分配工作，以及承擔被批評的情緒。
3. **人生有變數**：孩子特質、家庭資源、外界反應與偶發事件不由玩家完全控制。
4. **允許修復與支持**：疲憊、衝突與失誤有後續修復；也有陌生人的善意和伴侶支持。
5. **有依據的知識，不把科學遊戲化成評分**：知識卡與遊戲效果分離，標明可驗證來源及審查狀態。

**不做的事**：判定「好／壞父母」、預測孩子真實人格或未來、用單一選擇造成不可逆的心理創傷、把母親預設為唯一主要照顧者、用玩家測驗推斷家庭收入或孩子氣質。

## 2. 玩家與體驗目標

- **玩家**：現任或準父母、其他照顧者、想理解育兒生活的大眾。
- **遊戲長度**：首發每局約 10–15 分鐘；12 個主要回合；可隨時存續。
- **體驗節奏**：共鳴與壓力 → 實際選擇 → 敘事回饋 → 偶發支持／轉折 → 反思與修復。
- **結束感受**：「我做的選擇受到處境影響」「照顧者也需要被照顧」「可以重玩不同的人生」。
- **語言**：台灣繁體中文、自然不說教的敘事語氣。

## 3. 發布範圍：先有可玩的 30 件事，再擴充內容

| 項目 | 首發 MVP | 後續擴充 |
|---|---|---|
| 年齡 | 0–6 歲 | 7–18 歲另評估 |
| 一局 | 12 回合 | 多章節、單日模式 |
| 事件 | 30 件完整可玩、含連鎖事件 | 100 件；內容路線圖可擴至 150+ |
| 開場 | 5 題**可跳過**的照顧傾向情境題 | 更多敘事風格與進階設定 |
| 家庭 | 4 類家庭結構，隨機工作／資源／孩子特質 | 更多共同照顧與社會支持配置 |
| 指標 | 5 項可見資源＋隱性規劃負擔與敘事旗標 | 更完整的分工與時間預算 |
| 知識 | 首發事件關聯的審查過或明確標示草稿之知識卡 | 持續更新專業來源 |
| 進度 | LocalStorage 自動存檔 | 跨裝置存檔（須另設後端） |
| 分享 | 不含敏感資訊的結局文字分享 | 圖卡分享 |
| 部署 | Cloudflare Pages 靜態託管 | 視成長需求決定後端 |

**MVP 完成定義**：無需註冊即可開始、完成 12 回合、看到結局與知識卡；不同 seed 產生不同故事，固定 seed 可重現；頁面重整可繼續；手機使用流暢；自動化測試通過。

## 4. 遊戲循環與時間

1. **開場（選用）**：5 個情境題，僅產生多維度的敘事偏好，不作心理診斷。
2. **家庭抽選**：家庭結構、照顧分工、工作彈性、經濟餘裕、支持網絡、孩子氣質。可重抽。
3. **事件回合**：選取年齡適合、符合先前情節的事件；描述當下處境及可用選項。
4. **選擇**：玩家面對 2–4 個均有其合理性的處理方式；選項有條件限制。
5. **結果**：更新資源、紀錄行動、安排後續事件；外界可能支持、冷淡、批評或沒有反應。
6. **可選知識卡／內心獨白**：可閱讀，不打斷主要遊戲節奏。
7. **進入下一回合**：年齡依預先定義的 12 回合里程碑前進，直到結局。
8. **家庭回顧**：列出關鍵經歷、修復與支持時刻、敘事結局，可重新抽取人生。

12 回合可採年齡里程碑月份 `[2, 6, 10, 15, 21, 27, 33, 39, 45, 52, 61, 71]`；實作時將它作為獨立設定，避免將「一年只有兩件事」誤認為現實生活頻率。每回合是代表性的故事片段。

## 5. 家庭生成與角色

**家庭結構**：雙薪共同照顧、單親家庭、多代同住家庭、一人全職照顧家庭。每一種都可能有不同支持程度與工作彈性，不預設道德或教養優劣。角色語言以「照顧者／伴侶／家人」優先，劇情可以呈現母親常承擔的不公平期待，但避免硬編碼「媽媽必須煮飯」。

**孩子氣質（敘事標記而非診斷）**：活動量、敏感程度、轉換活動所需時間、適應陌生環境節奏。孩子的氣質不應等於「乖／壞」。

**外部條件**：工作與請假彈性、是否有同行照顧者、住家交通可及性、預算狀態、臨時支援。隨機權重若無來源應明確標記為虛構遊戲平衡參數。

## 6. 狀態系統

**玩家可見資源（0–100）**：`finances`（經濟餘裕）、`energy`（照顧者精力）、`support`（可用支持）、`timeFlexibility`（時間彈性）、`connection`（親子連結）。這些是遊戲抽象指標，不是心理量表。

**隱性或柔性狀態**：`planningLoad`（記得、決策、協調等持續規劃負荷）、`stressContext`（近期疲勞與壓力背景）、`relationshipRepair`、`narrativeTendencies`（開場偏好及後續演變）、`flags`（重大事件與對話）、`scheduledFollowUps`、`choiceHistory`。

**重要規則**：選項可消耗資源，但不以單次選擇決定孩子的人格或家庭命運；影響可以透過支持、休息、分工與道歉修復；玩家不會因「外食、偶爾用手機、請求幫忙」受到固定道德處罰。

### 6.1 看不見的勞動

同一件家務至少可區分 `notice`（察覺需求）、`plan`（規劃）、`coordinate`（通知／分配）、`execute`（執行）、`followThrough`（追蹤完成）。劇情展示「伴侶有做，但還是要我提醒」與「伴侶主動承擔整個流程」的差異，不只計算誰動手。

### 6.2 外界反應

每次公共場合事件應有 `reactionPool`：`criticism`、`support`、`neutral`、`none`；另有 `anticipatedJudgment`（父母預期被看待）與 `observedReaction`（實際出現的反應），避免把陌生人的一個眼神直接寫成批評。

## 7. 開場照顧傾向情境題

可跳過；5 題各 4 個選項，約 1 分鐘。題目包含：疲累時的晚餐、餐廳孩子哭鬧、孩子睡後的家務、親友教養評論、難得的空閒時間。選項映射到多維度（責任優先、彈性調整、自我照顧、共同分擔），不可簡化成每題 A/B/C/D 對應相同分數。

**結果用途**：開場內心獨白、敘事角度、小幅事件權重變動。**不得用於**：決定家庭財富、孩子氣質、限制選項、決定「教養成功」、固定結局。

顯示為「目前的情境傾向」，不宣稱「你是某型媽媽」。允許並列、混合結果與隨故事改變。

## 8. 事件內容架構

### 8.1 長期分類（建議擴充方向）

1. 每日三餐與備餐規劃
2. 清潔、收納與家務
3. 預約、通知與用品管理
4. 工作、請假及職涯
5. 公共交通與外出
6. 餐廳與公共場合
7. 社會眼光與長輩期待
8. 伴侶分工與溝通
9. 父母自我認同、休息與心理負擔
10. 幼兒飲食、睡眠與日常照顧
11. 健康、安全與醫療安排
12. 托育、幼兒園與同儕
13. 金錢、消費與家庭財務
14. 正向支持與陌生人善意
15. 關係修復、共同成長與喜悅

### 8.2 代表性事件鏈 A：晚餐

`下班後要不要煮飯` → `孩子不想吃`／`今晚選外食`／`家庭成員主動承擔` → `誰負責收拾` → `下週菜單誰規劃`。

可行選擇：完整自煮、簡單料理、外食、與家人協調分工；需要同行照顧者的選項只能在角色存在時出現。結局不保證好壞，外食不可預設「營養差」，自煮不可預設「一定健康」。

### 8.3 代表性事件鏈 B：大眾運輸

`捷運孩子哭鬧` → `安撫／手機短暫轉移注意／下車休息／家人接手` → `旁人支持／中立／批評／無反應` → `孩子疲累且隔天要上班`。

交通安全優先：不能提供違反行車安全的建議；交通規範以發布前核實的官方資訊為準。

### 8.4 代表性事件鏈 C：餐廳

`孩子吵鬧` → `提醒後孩子大哭` → `抱到外面／一起遊戲／短暫手機安撫／同行者接手` → `旁人的不同反應` → `父母內心獨白與關係修復`。

### 8.5 代表性事件鏈 D：看不見的規劃

`幼兒園通知要帶用品` → `照顧者忙忘` → `誰記得、誰採買、誰準備` → `伴侶只等待指示或主動認領整項工作` → `重新分工的對話`。

### 8.6 代表性事件鏈 E：父母情緒

`連日睡不好` → `失去耐心` → `擔憂自己不是好父母` → `休息／求助／與孩子修復／伴侶協調` → `更有彈性的後續故事`。

## 10. 事件資料規格

每個 `EventDefinition`：
- `id`, `title`, `category`, `tags`, `ageMinMonths`, `ageMaxMonths`, `weight`
- `eligibility`：含家庭角色、flags、資源條件與前置事件
- `scene`：情境敘事
- `choices[]`：`id`, `text`, `requirements`, `resourceDeltas`, `setFlags`, `reflectionByTendency`, `immediateOutcomes`, `followUpRules`
- `reactionPool`：可選，定義外界實際反應；與主角預期區別
- `knowledgeCardIds[]`：可選，關聯來源卡片
- `repeatable`, `cooldownTurns`, `contentReviewStatus`

**注意**：外界反應與後續故事也由 seeded PRNG 決定；切忌一個選項強制導向「被批評」；選項不可因家庭無伴侶卻顯示「請伴侶接手」。

**運作示意**：
```ts
type ResourceKey = 'finances' | 'energy' | 'support' | 'timeFlexibility' | 'connection';

type SocialReactionKind = 'support' | 'neutral' | 'criticism' | 'none';

interface GameState {
  schemaVersion: number;
  seed: number;
  rngState: number;
  turn: number;
  childAgeMonths: number;
  resources: Record<ResourceKey, number>;
  planningLoad: number;
  family: FamilyProfile;
  tendencies: Record<string, number>;
  flags: string[];
  completedEventIds: string[];
  scheduledFollowUps: ScheduledEvent[];
  history: StoryEntry[];
}
```

### 10.1 抽選演算法

1. 優先檢查符合年齡與條件的排程後續事件；僅在規格允許時覆蓋一般事件。
2. 一般事件依年齡、家庭、前置條件、冷卻／去重過濾。
3. 套用權重（含開場偏好至多小幅調整），以 seeded PRNG 選取。
4. 由同一 PRNG 推導後續外界反應與分支，讓相同 seed + 相同選擇可以重播。
5. 候選池為空時啟用安全備援事件，確保 12 回合可完成。
6. 每次狀態更新應為純函式，保留事件歷史供除錯。

## 11. 育兒知識卡與內容治理

知識卡是**可選閱讀**，不當作選項正誤提示。資料欄位：`id`, `topic`, `ageRange`, `summary`, `practicalTips`, `sourceOrganization`, `sourceTitle`, `sourceUrl`, `reviewStatus`, `lastReviewedAt`, `medicalDisclaimer`。

**可靠來源優先序**：台灣官方衛生及育兒機構、WHO、UNICEF、CDC、其他有明確研究依據的正式資料。來源與建議必須逐張核實；無法核實則標示「待查核草稿」，不得暗示已經專業認證。健康與安全資訊不可取代醫療診斷或緊急處置。

**公開論壇研究紀錄**：另建 `docs/RESEARCH_BACKLOG.md` 記來源平台、公開網址、日期、核心矛盾、事件提案、查核與敏感度狀態。Threads 討論作為情境靈感，而不是代表性統計資料；劇情不得原樣複製可辨識當事人的私人敘述。

## 12. 結局與故事回顧

六個非排名的敘事主題：
1. 一起慢慢長大
2. 忙碌的雙薪日常
3. 有人同行的旅程
4. 學著照顧自己
5. 一邊衝突一邊修復
6. 意想不到的成長

不必與特定家庭結構一對一綁定。一局可以產生一個主要主題與一至兩個次要主題，附上三個重要選擇、至少一個難忘時刻、學到的資源或支持方式，以及重新遊玩入口。結果是角色故事，不是對真實父母的評語。

## 13. UI / UX

**設計語言**：溫暖繪本、紙雕或柔和插畫；不使用帶羞辱性的扣分動畫。手機優先，容易單手操作，文字短段落呈現。

**畫面**：首頁 → 可跳過開場情境 → 家庭抽選 → 事件卡與選擇 → 結果／內心獨白 → 可選知識卡 → 12 回合時間線 → 故事結局與文字分享。

**可及性**：對比、鍵盤可操作、焦點可見、文字替代資訊、尊重減少動態效果；不要依賴顏色辨別唯一狀態。

**隱私**：不要求真實姓名、孩子生日或心理健康資訊；問卷結果僅在本機儲存，可跳過／清除。分享內容須避免自動包含敏感個資。

## 15. 測試與驗收

**單元測試**：固定 seed 重現；家庭生成欄位合法；年齡與前置條件有效；只有符合家庭成員條件才可選；資源 clamping；規劃負擔計算；外界反應池合法；後續事件不形成無限循環；事件去重；12 回合可結局；存檔版本／損壞存檔安全恢復；所有 JSON 能通過 Zod 驗證。

**端對端測試**：開始遊戲／跳過問卷／完成問卷／12 回合完成／檢視知識卡／重整續玩／重開一局／手機窄畫面／鍵盤操作／離線或資料損壞提示。

**內容驗收**：全部 30 個 MVP 事件有 2–4 個具體選項、至少部分支援社會反應與後續事件、沒有預設媽媽負責家務、沒有以單次選擇斷言發展結果；知識卡來源逐張核查或清楚標示待審。

## 16. 實作分期（Codex）

- **階段 1：文件與技術設計**——PRD、GDD、JSON schema 草案、測試計畫；完成後停止審查。
- **階段 2：純 TypeScript 引擎**——狀態、seed、事件選擇、後續事件、外界反應、結局及 Vitest。
- **階段 3：可玩 UI**——開場、家庭、選項、結果、進度、存檔、結局；先放 6–10 個範例事件。
- **階段 4：內容擴至 30**——補足代表性事件、知識卡、修復及支持分支，完成內容審核。
- **階段 5：品質與發布**——Playwright、效能、無障礙、分享、Cloudflare Pages。
- **階段 6：擴充**——優先增加可玩事件至 100；依玩家測試再評估 150+ 事件、章節及其他系統。

## 17. 風險與對策

- **內容過量**：先 30 完整事件，不以 100 個題目取代可玩性。
- **表面上只有選擇題**：每局應包含至少兩個跨回合的事件連鎖、一次支持／修復機會。
- **社會壓力過度負面**：反應池含中立、支持和無反應，敘事兼顧溫暖。
- **心理測驗誤用**：開場測驗只做敘事傾向、可跳過、不診斷。
- **教養資訊失準**：知識與虛構後果分離，保留查核紀錄。
- **家庭刻板印象**：角色中立建模，避免用家庭結構指定能力或好壞。
- **存檔兼容性**：schemaVersion + migration/fallback。
- **部署費用**：靜態託管起步，部署前檢查服務方案限制。

## 18. 待決策項目

1. 畫風：紙雕繪本／水彩手繪／簡約漫畫（可在 UI 原型後比較）。
2. 敘事主角：第一人稱「你」為主，媽媽／爸爸是否可選稱謂。
3. 事件比重：隱形負擔、孩子照顧、支持事件的首發比例。
4. 知識卡：公開前是否安排專業審查；未審資訊如何標示。
5. 完整事件庫的維護方式：純 JSON、內容試算表或輕量 CMS。
